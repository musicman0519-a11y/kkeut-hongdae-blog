# 어드민 → 사이트 연동 (칼럼 발행 스크립트)

작성일: 2026-10-24 · 상태: 승인됨 (2026-10-24, 도메인 blog 로 확정)

## 문제 / 목적
`kkeut_admin.html` 에서 칼럼 HTML 을 만든 뒤 사이트에 반영하려면 ① 파일을 `kkeut_seo_site/` 에 넣고 ② `columns.html` 목록 코드를 붙여넣고 ③ `sitemap.xml` 에 한 줄을 추가하는 일을 손으로 해야 한다. 세 군데를 따로 고치면 빠뜨리거나 어긋난다. 개발자(사용자 본인)가 터미널 명령 한 번으로 세 가지를 한꺼번에, 같은 규칙으로 반영하게 한다.

## 범위 (In)
- 로컬 스크립트 하나. 입력은 **어드민에서 다운로드한 `column-<slug>.html` 파일 경로** 하나.
- 스크립트가 하는 일:
  1. 입력 파일에서 제목·태그·날짜·요약을 읽는다. (어드민 `buildPage` 가 만드는 구조 기준: `<h1>` 제목, 「원장 칼럼 · 태그」 줄, 「날짜 · 홍대 끗 한의원 원장」 줄, 본문 텍스트 앞 90자 요약)
  2. `kkeut_seo_site/column-<slug>.html` 로 복사한다. 이때 `canonical` 과 `og:url` 의 도메인이 사이트 도메인 `https://blog.kkeutclinic-hongdae.co.kr` 과 다르면 맞춘다. (어드민 설정값을 바꿔 둔 경우의 보험)
  3. `columns.html` 의 목록 `<ul class="divide-y divide-black/10">` **맨 위**에 새 `<li>` 를 넣는다. 마크업은 기존 항목과 동일(태그 / 제목 / 요약 / 「날짜 · 원장 칼럼」).
  4. `sitemap.xml` 의 `</urlset>` 앞에 `<url><loc>…</loc></url>` 한 줄을 넣는다.
  5. 바뀐 파일 3개와 최종 URL 을 출력한다.
- 안전장치:
  - 같은 slug 파일이 이미 있으면 **아무것도 바꾸지 않고** 중단한다(덮어쓰기 없음).
  - 목록·사이트맵에 같은 파일명이 이미 있으면 중복으로 넣지 않는다.
  - 입력 파일이 어드민 구조가 아니면(제목·날짜 줄을 못 찾으면) 아무것도 바꾸지 않고 중단한다.
  - 세 파일 중 하나라도 실패하면 나머지도 바꾸지 않는다(전부 성공 또는 전부 안 함).
- `--dry-run` 옵션: 바뀔 내용만 출력하고 파일은 건드리지 않는다.

## 범위 밖 (Out)
- **git commit / push / 배포.** 호스팅이 아직 미정이므로 스크립트는 로컬 파일만 바꾼다.
- `index.html` 첫 화면 「원장 칼럼」 섹션 갱신. (사용자 결정: 첫 화면은 직접 관리)
- 이미 발행된 글의 수정·삭제·순서 변경. (신규 발행만)
- `kkeut_admin.html` 의 화면·기능 변경. (GitHub 토큰, 자동 커밋, 안내문 수정 포함 — 미결 1 참조)
- 어드민의 localStorage 초안을 브라우저 밖에서 직접 읽는 것.
- 이미지 최적화, HTML 유효성 검사, 깨진 링크 검사.
- 기존 칼럼 2개(`column-jemo-shaving`, `column-summer-skin-care`)를 스크립트로 다시 만드는 것.
- 여러 파일을 한 번에 발행하는 것(한 번에 한 글).

## 사용자 흐름
1. 어드민에서 글 작성 → 「발행 파일 만들기」 → 「다운로드」. 예: `~/Downloads/column-winter-care.html`
2. 프로젝트 루트에서 터미널 명령 한 번. (명령 이름과 위치는 `/plan` 에서 정함)
   ```
   <발행 명령> ~/Downloads/column-winter-care.html
   ```
3. 스크립트가 읽어낸 제목·태그·날짜·요약·최종 URL 과 바꿀 파일 3개를 출력한다.
4. 성공: 세 파일이 바뀌고 요약이 출력된다. 실패: 한 파일도 바뀌지 않고 이유가 출력된다.
5. (범위 밖) 사용자가 직접 확인 후 커밋·배포한다.

## 완료 기준
- [ ] 어드민으로 만든 `column-test.html` 을 넣고 실행하면 `kkeut_seo_site/column-test.html` 이 생기고, 그 안의 `canonical` 과 `og:url` 이 `https://blog.kkeutclinic-hongdae.co.kr/column-test.html` 이다.
- [ ] 실행 후 `columns.html` 의 `<ul>` 첫 번째 `<li>` 가 새 글이고, 태그·제목·요약·날짜 텍스트가 어드민에 입력한 값과 같다. 기존 2개 항목은 그 아래에 그대로 남아 있다.
- [ ] `sitemap.xml` 에 새 URL 이 정확히 한 줄 추가되고, 기존 16개 URL 은 유지되며, 파일이 여전히 유효한 XML 이다.
- [ ] 같은 파일로 두 번 실행하면 두 번째는 "이미 존재" 메시지와 함께 종료 코드 1 로 끝나고, 세 파일 모두 변경이 없다.
- [ ] `--dry-run` 으로 실행하면 변경 예정 내용이 출력되고, 세 파일 내용은 실행 전과 바이트 단위로 같다.
- [ ] 입력 파일에 `<h1>` 이 없거나 어드민 구조가 아니면 종료 코드 1, 세 파일 변경 없음.
- [ ] 제목·요약에 `<`, `&`, `"` 가 있어도 `columns.html` 과 `sitemap.xml` 에서 올바르게 이스케이프되어 들어간다.
- [ ] 파일명이 `column-` + 영문 소문자·숫자·하이픈 + `.html` 형식이 아니면 거부한다(종료 코드 1).
- [ ] 사진이 많이 들어간 수 MB 짜리 파일도 같은 결과로 처리된다.
- [ ] Windows Git Bash/PowerShell 과 macOS 터미널에서 같은 명령으로 동작한다.

## 제약
- **기술 스택**: Node.js 단일 파일, 외부 패키지 없음(`package.json` 없이도 실행). 로컬에 Node v25, Python 3.14, git 2.53 설치 확인됨. 사이트가 JS 생태계(Tailwind)라 Node 를 택함.
- 사이트는 빌드 도구 없는 정적 HTML. 스크립트는 **지정한 삽입 지점 외에는 기존 파일의 한 글자도 바꾸지 않는다.** 들여쓰기(2칸)와 줄바꿈 스타일은 기존 파일을 따른다.
- 새 칼럼 파일의 마크업은 어드민 `buildPage` 출력 그대로 둔다(도메인 치환만).
- `columns.html` 항목 마크업은 어드민이 「목록 코드」로 뿌려 주는 것과 동일하게 유지해 수작업 결과와 구분이 없게 한다.
- CLAUDE.md, `/constraints` 규칙은 아직 없음.

## 가정 / 미결 질문
**가정**
- 사이트 도메인은 `https://blog.kkeutclinic-hongdae.co.kr` 이다 (2026-10-24 확정. `www.` 는 운영 중인 Next.js 본사이트라 쓸 수 없음). 사이트의 canonical·sitemap·robots 와 어드민 기본값이 모두 이 값으로 통일돼 있다. DNS 는 아직 없다.
- 요약은 어드민과 같은 규칙(본문 텍스트 앞 90자)으로 만든다. `meta description` 은 쓰지 않는다(꼬리말 「홍대 끗 한의원 원장 칼럼.」이 붙어 있음).
- 날짜는 어드민 입력 문자열 그대로 쓴다(예: `2026. 07.`). 형식 검증은 하지 않는다.
- 목록은 최신 글이 맨 위다.
- 스크립트는 프로젝트 루트의 `scripts/` 폴더에 둔다.
