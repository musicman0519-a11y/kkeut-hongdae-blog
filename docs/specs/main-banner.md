# 메인 배너 (첫 화면 상단 움직이는 배너)

작성일: 2026-10-30 · 상태: **삭제됨 (2026-11-04)** — 사용자 결정으로 배너 섹션·영상 자산 제거. v1 구현 완료(2026-10-30) 및 v2(AI 영상 교체) 계획은 기록용

## 문제 / 목적
첫 화면(index.html)은 로고·메뉴 아래에 글 한 줄("일요일에도 진료합니다")과 버튼만 있어 첫인상이 밋밋하다. 디자인 팀이 만든 「메인 배너 활용.gif」(모델 사진 + 로고 + 문구 + 메뉴 4개가 들어간 움직이는 배너)를 첫 화면 맨 위에 보여 주어 브랜드 인상을 주고, 배너 안의 메뉴로 바로 이동하게 한다.

## 조사로 확인한 사실 (2026-10-30)
- 파일: 프로젝트 루트의 `메인 배너 활용.gif`. **19.7MB**, 2390×821(약 2.9:1), 29프레임 × 0.1초 = 2.9초 무한 반복.
- 움직임은 모델의 눈 깜빡임과 미세한 동작뿐이다(짧은 영상 루프). 로고·문구·메뉴 글자는 고정이며 **이미지 안에 박혀 있다.** 메뉴 글자(About Us / Official Website / KakaoTalk / Reservation)는 그림일 뿐 눌리지 않는다.
- GIF 그대로 올리면 첫 화면이 20MB 가 되어 모바일에서 첫 화면이 수십 초 걸린다. 반드시 변환해야 한다. 로컬에 ffmpeg 9 이 있다.
- 세로로 짧은 가로형(2.9:1)이라 폰(390px)에서는 높이 134px 띠가 되고 글자를 읽을 수 없다.

## 범위 (In)
1. **영상 변환**: GIF 를 MP4(H.264) 와 WebM 으로 변환해 `kkeut_seo_site/assets/banner/` 에 둔다. 첫 프레임을 포스터 이미지(JPG)로 뽑는다. 원본 GIF 는 사이트 폴더에 넣지 않는다.
2. **배너 섹션**: 메뉴(nav) 바로 아래, 「일요일에도 진료합니다」 섹션 위에 전체 폭 배너 섹션을 추가한다. `<video autoplay muted loop playsinline>` + 포스터. 영상이 못 뜨는 환경(저장 데이터 모드, 재생 불가)에서는 포스터가 그대로 보인다.
3. **배너 안 메뉴 4개를 진짜 링크로**: 글자 위치가 고정이므로 그 자리에 보이지 않는 링크 영역(퍼센트 좌표)을 얹는다. About Us → `about.html`, Official Website → 본사이트(www), KakaoTalk → 페이지에 이미 쓰는 카카오 채널 링크, Reservation → `#booking`. 키보드 포커스·스크린리더용 이름을 넣는다.
4. **모바일 대응**: 폰 폭에서는 배너를 가운데(모델 얼굴 + 문구) 기준으로 잘라 높이를 확보한다. 글자가 어차피 작아 읽기 어려우면 모바일에서는 링크 영역을 숨기고 배너를 그림으로만 보여 준다.
5. **성능·접근성 보호**: 포스터를 미리 불러오게(preload) 하고 영상은 메타데이터만 먼저 받는다. `prefers-reduced-motion` 사용자는 영상 대신 포스터만 본다. 첫 화면 다른 요소의 위치가 로딩 중에 밀리지 않도록 배너 높이를 미리 잡는다.

## 범위 밖 (Out)
- 배너 **내용** 수정(문구·메뉴 글자·사진 교체). 이미지에 박혀 있어 디자인 원본 없이는 못 바꾼다. 미결 1 참조.
- 여러 장을 넘기는 슬라이드 배너. 이번에는 한 장.
- 다른 페이지(시술·칼럼)의 배너.
- 로고 헤더·메뉴를 배너 안으로 합치거나 없애는 것. 헤더·메뉴는 그대로 둔다.
- 모바일 전용 세로형 배너 제작(세로 소스가 오면 별도 작업).
- 「일요일에도 진료합니다」 섹션 삭제. 배너 아래에 그대로 둔다.

## 사용자 흐름
1. 방문자가 index.html 을 연다 → 로고·메뉴 아래에 배너가 바로 보인다(처음엔 포스터, 곧 영상이 소리 없이 반복 재생).
2. 배너 속 "Reservation >" 을 누르면 예약 섹션으로, "About Us >" 는 소개 페이지로, "Official Website >" 는 본사이트 새 탭으로, "KakaoTalk >" 은 카카오 채널로 간다.
3. 폰에서는 얼굴과 문구가 보이는 부분이 잘린 배너가 보이고, 그 아래 기존 흐름(일요일 진료 → 시술 메뉴)이 이어진다.

## 완료 기준
- [x] `assets/banner/` 에 MP4, WebM, 포스터 JPG 가 있고 MP4 ≤ 1.5MB, WebM ≤ 1.5MB, 포스터 ≤ 200KB 이다. 원본 GIF 는 `kkeut_seo_site/` 안에 없다.
- [x] 데스크톱(1280px)에서 index.html 을 열면 메뉴 아래에 배너가 전체 폭으로 보이고, 로딩 2초 뒤 스크린샷 두 장(0.5초 간격)이 서로 다르다(재생 중).
- [x] 영상 태그에 `autoplay muted loop playsinline poster` 가 모두 있고, 영상 파일을 지워도 포스터가 같은 자리에 같은 크기로 보인다.
- [x] 배너 위 네 글자 자리에 링크가 있어, 각 글자 중심 좌표를 클릭하면 정해진 네 목적지로 간다. Tab 키로 네 링크에 차례로 포커스가 가고 이름이 읽힌다.
- [x] 폰(390px, 에뮬레이션)에서 배너 높이가 200px 이상이고 모델 얼굴이 보이며, 가로 넘침 요소가 0개다.
- [x] `prefers-reduced-motion: reduce` 를 켜고 열면 영상이 재생되지 않고 포스터만 보인다.
- [x] 배너 추가 전후 index.html 의 Lighthouse 모바일 성능 점수 차이가 5점 이내이고, CLS 가 0.1 이하다.
- [x] 다른 15개 페이지는 바이트 단위로 변경이 없다.

## 제약
- 순수 정적 HTML + Tailwind CDN. 빌드 없음. 영상 변환은 로컬 ffmpeg 로 한 번 하고 결과 파일을 커밋한다. 변환 명령은 `scripts/` 에 남겨 재현 가능하게 한다.
- 링크 영역 좌표는 퍼센트로 두어 배너가 어떤 폭이어도 글자 위에 맞도록 한다. 배너 비율(2390:821)을 CSS 에 고정한다.
- 기존 헤더·메뉴·「일요일」 섹션 마크업은 건드리지 않는다. 배너 섹션은 nav 와 그 섹션 사이에 끼워 넣기만 한다.
- 소리 없음(muted)이 아니면 브라우저가 자동 재생을 막으므로 소리는 쓰지 않는다.
- 모바일 확인은 CDP 에뮬레이션으로 한다(헤드리스 `--window-size` 는 가짜 넘침을 보인다).

## 가정 / 미결 질문
**가정**
- "맨 위" = 로고·메뉴 **아래**, 본문 맨 위. 로고 헤더보다 위에 두면 브랜드 로고가 두 번 보이므로.
- 메뉴 4개의 목적지는 위 3번과 같다. 특히 "Official Website" 는 본사이트(www) 새 탭.
- 모바일은 가운데 기준으로 자른다. 자른 뒤 글자가 안 읽히면 링크 영역은 모바일에서 뺀다.
- 「일요일에도 진료합니다」 섹션은 배너 아래 그대로 둔다.

**결정 (2026-10-30, 사용자 답변)**
1. 글자 없는 원본은 없음. 배너는 우리 소유 자산이라 그대로 올린다 → 그림 위 투명 링크 방식 확정.
2. 모바일은 가운데 자르기(얼굴+문구가 보이도록, 높이 240px 안팎). 링크 영역은 모바일에서 숨긴다.
3. KakaoTalk 링크는 "그대로" 쓰기로 했으나, 이 사이트의 `pf.kakao.com` 링크는 채널 ID 가 없는 자리표시자로 확인됨(2026-10-30). 본사이트(www)에 있는 실제 채널 `https://pf.kakao.com/_xgTJnX/chat` 를 쓴다.

## v2 변경 (2026-11-04) — AI 영상 교체·글자 제거
