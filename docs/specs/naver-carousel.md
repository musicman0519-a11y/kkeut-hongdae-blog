# 네이버 검색 캐러셀 노출 (일산한의원 사례처럼 보이기)

작성일: 2026-10-27 · 상태: 승인 대기

## 문제 / 목적
네이버에서 "일산한의원"을 검색하면 다온한의원 사이트가 **사이트 이름 + 제목 + 설명 + 하위 페이지 이미지 카드 슬라이드(캐러셀)** 형태로 크게 나온다. 끗 한의원도 네이버에서 같은 형태로 보이게 하고 싶다. 카드 한 장이 시술 하나라서 검색 결과에서 차지하는 면적과 클릭률이 일반 링크보다 훨씬 크다.

## 조사로 확인한 사실 (2026-10-27)
- 그 캐러셀은 네이버 서치어드바이저 공식 가이드의 **「캐러셀 (ListItem)」 구조화 데이터**다. 사이트 첫 페이지 `<head>` 에 `ItemList` JSON-LD 를 넣고, 항목마다 `image`(필수)·`name`·`url`(절대 경로) 을 적는다.
- 예시 사이트(vanillamonaco.com)를 직접 뜯어 보니 첫 페이지에 하위 페이지 6개짜리 `ItemList` 가 있고, 카드의 그림·제목이 그 6개와 정확히 일치한다. og:image 는 없었다. 즉 **카드는 og 태그가 아니라 ItemList 에서 나온다.**
- 네이버 가이드 규칙: 한 페이지에 ItemList 하나, 항목이 적으면 노출 안 함(실무에서는 5개가 경계선), 이미지는 원본·항목별로 다른 것·로고나 기본 이미지 금지, 페이지에 실제로 없는 항목을 적으면 스팸.
- 노출은 보장되지 않고 네이버가 판단한다. 적용 후 수일에서 수주가 걸린다.
- **끗 한의원 본사이트(www)** 는 이미 서치어드바이저 소유 확인·sitemap·Organization 구조화 데이터·og:image 를 갖췄지만 ItemList 는 없다. 브랜드 검색("홍대 끗 한의원")의 사이트 결과는 이 www 가 차지할 가능성이 크다.
- **이 SEO 사이트(blog.)** 는 아직 배포·DNS·서치어드바이저 등록이 없다. 노출 이전에 "존재"부터 만들어야 한다.

## 범위 (In)
이 저장소에서 할 수 있는 것, 곧 SEO 사이트(blog.kkeutclinic-hongdae.co.kr) 기준이다.
1. **첫 페이지 ItemList 구조화 데이터**: index.html `<head>` 에 시술 페이지를 항목으로 하는 ItemList JSON-LD 하나. 항목은 index 시술 메뉴 순서대로 11개(제모, 리프팅, 토닝, 여드름, 스킨부스터, 스킨케어, 윤곽·쁘띠, 다이어트, 안티에이징, 안티에이징센터, 흉터재생센터). 각 항목의 `url` 은 절대 경로, `name` 은 검색 결과에서 읽히는 한 줄(예: "홍대 리프팅 — 온다·볼뉴머·슈링크, 탄력은 더하고 통증은 줄이는 시술").
2. **카드 이미지 11장**: 항목마다 서로 다른, 정사각형에 가까운(600×600 이상) 원본 이미지. 지금 index 에 쓰는 사진 + 시술명 텍스트를 얹은 카드 형태로 만들어 `assets/cards/` 에 둔다. 예시 사이트도 텍스트 얹은 카드로 통과했다.
3. **첫 페이지 FAQPage 구조화 데이터**: 예시 사이트처럼 자주 묻는 질문 3~5개. 본문에 실제로 보이는 질문만 적는다(페이지에 없는 내용은 스팸).
4. **첫 페이지 og:image**: 1200×630 대표 이미지 1장. 카드와는 별개로, 링크 공유와 일반 검색 썸네일용.
5. **사이트 제목·설명 정리**: index `<title>` 과 description 을 "브랜드 + 지역 + 핵심 시술" 한 줄로. 예시처럼 동네 이름 나열은 하지 않는다(네이버가 "사이트 제목과 설명은 엄격 관리"라고 명시).
6. **네이버 서치어드바이저 준비물**: 소유 확인용 `naver-site-verification` 메타를 16페이지 공통 head 에 넣을 자리, sitemap.xml 과 robots.txt 는 이미 있음(blog 도메인으로 통일 완료). RSS 는 칼럼 2개 + 어드민 발행 글로 `rss.xml` 생성.
7. **검증 절차 문서**: validator.schema.org 로 마크업 검출 확인 → 서치어드바이저 등록·sitemap/RSS 제출 → 2주 뒤 브랜드 검색 확인, 의 체크리스트를 `docs/` 에 남긴다.

## 범위 밖 (Out)
- **본사이트(www, Next.js)에 ItemList 넣기.** 가장 효과가 빠른 길이지만 다른 저장소다. 미결 1 참조. 여기서는 그 사이트에 붙여 넣을 수 있는 JSON-LD 조각만 결과물로 함께 준다.
- 배포·DNS·호스팅 선택. (별도 명세. 단, 이 명세의 완료 기준 일부는 배포 뒤에만 확인 가능하므로 선행 조건으로 적는다.)
- 네이버 플레이스·블로그·광고 등 사이트 밖 채널.
- 구글 리치 결과(구글은 캐러셀을 레시피·영화 등 일부 타입만 지원). 구글용으로는 1·3·4번이 그대로 도움이 되지만 따로 손대지 않는다.
- 칼럼 페이지를 캐러셀 항목으로 넣는 것(시술 11개로 충분하고, 칼럼은 늘어나므로 별도 ItemList 가 필요해 "한 페이지 하나" 규칙과 충돌).
- 검색 순위 자체(백링크, 콘텐츠 마케팅).

## 사용자 흐름
사용자 = 네이버 검색 이용자 / 운영자 = 원장님·개발자

1. 운영자: 이 명세대로 index.html 과 카드 이미지를 만들고 배포한다.
2. 운영자: 서치어드바이저에 blog 도메인을 등록, 소유 확인, sitemap·RSS 제출.
3. 네이버 로봇: 첫 페이지를 수집하고 ItemList 를 읽는다. (수일~수주)
4. 이용자: "홍대 끗 한의원" 또는 "홍대 피부 시술 한의원" 검색 → 사이트 결과에 제목·설명·시술 카드 슬라이드가 보인다 → 카드를 누르면 해당 시술 페이지로 간다.

## 완료 기준
배포 전에 확인 가능:
- [ ] index.html 에 `ItemList` JSON-LD 가 정확히 1개 있고, 항목 11개의 `url` 이 모두 `https://blog.kkeutclinic-hongdae.co.kr/…html` 절대 경로이며 각 파일이 실제로 존재한다.
- [ ] 11개 항목의 `image` 가 서로 다른 파일을 가리키고, 각 파일이 존재하며 가로·세로 600px 이상이고 로고가 아니다.
- [ ] 항목 `name` 11개가 모두 해당 시술 페이지의 `<h1>` 또는 index 메뉴 카드 문구와 내용이 일치한다(페이지에 없는 항목 없음).
- [ ] index.html 에 `FAQPage` JSON-LD 가 1개 있고, 질문·답이 index 본문에 실제로 보인다.
- [ ] index.html 에 1200×630 `og:image` 가 있고 파일이 존재한다.
- [ ] 16페이지 모두 `<head>` 에 같은 위치의 `naver-site-verification` 자리(값은 등록 때 채움)가 있다.
- [ ] `rss.xml` 이 유효한 RSS 2.0 이고 칼럼 2개가 들어 있다.
- [ ] 두 JSON-LD 모두 `JSON.parse` 가 통과하고 validator.schema.org 에서 오류 0건.
- [ ] 본사이트용 ItemList JSON-LD 조각이 `docs/` 에 별도 파일로 있다(url 만 www 로 바꾼 버전).

배포 후에만 확인 가능(선행: 배포·DNS·서치어드바이저 등록):
- [ ] validator.schema.org 에 `https://blog.kkeutclinic-hongdae.co.kr/` 를 넣으면 ItemList 와 FAQPage 가 검출된다.
- [ ] 서치어드바이저에서 sitemap·RSS 가 "정상" 으로 표시된다.
- [ ] 2주 뒤 네이버 브랜드 검색에서 사이트 결과가 나온다. (캐러셀 노출 여부는 네이버 판단이라 완료 기준이 아니라 관찰 항목)

## 제약
- 순수 정적 HTML, 빌드 도구 없음. JSON-LD 는 각 HTML 에 직접 넣는다(외부 .json 파일 연결은 네이버가 못 읽는다는 사례 있음).
- 카드 이미지 생성은 수작업 디자인 대신 재현 가능한 방법(HTML 템플릿을 Chrome 헤드리스로 찍기 등)을 쓴다. 방법은 /plan 에서.
- 이미지 중복 금지: 현재 `slider-4.png` 와 `MainInfo_Left.png` 가 같은 파일이다. 둘 중 하나만 쓴다.
- 의료광고 표현 규칙: `name` 과 FAQ 답변에 "최고", "완치", "보장" 같은 표현을 쓰지 않는다.
- 어드민이 만드는 칼럼 페이지는 손대지 않는다(/spec admin-site-sync 범위).

## 가정 / 미결 질문
**가정**
- 대상 도메인은 `blog.kkeutclinic-hongdae.co.kr` (2026-10-24 확정).
- 캐러셀 항목은 시술 11개. 소개 페이지(about)는 뺀다.
- 카드 이미지는 사진 + 시술명 텍스트를 얹은 정사각 카드(예시 사이트 방식). 사진만 쓸지 텍스트를 얹을지는 디자인 판단이라 가정으로 둔다.
- 서치어드바이저 계정은 본사이트를 등록할 때 쓴 것을 그대로 쓴다.

**미결 질문**
1. **본사이트(www)에도 ItemList 를 넣을 수 있나?** 브랜드 검색의 사이트 결과는 www 가 가져갈 가능성이 크다. 그 사이트에 같은 JSON-LD 를 넣는 것이 캐러셀을 가장 빨리 보는 길이다. www 저장소에 접근 가능한지, 아니면 제작사에 전달할지.
2. 어떤 검색어에서 보이길 원하나? "홍대 끗 한의원"(브랜드) 인지 "홍대 피부과"·"홍대 한의원"(일반) 인지. 브랜드는 1번으로 해결되고, 일반 검색어는 이 SEO 사이트의 역할이며 캐러셀보다 순위 자체가 먼저다.
3. 배포는 언제·어디로? 이 명세의 후반 완료 기준은 배포 없이는 확인할 수 없다.
