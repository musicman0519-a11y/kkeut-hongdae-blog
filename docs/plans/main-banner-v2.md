# 메인 배너 v2 — AI 영상 교체·글자 제거 작업 계획 — **중단 (2026-11-04, 배너 섹션 삭제로 대체)**   (명세: docs/specs/main-banner.md 「v2 변경」 절)

작성일: 2026-11-04 · 현재 배너: `kkeut_seo_site/assets/banner/main.mp4` 1920×660 · **10fps** · 2.9초 · H.264 CRF 23 (GIF 29프레임에서 변환, 로고·문구·메뉴 4개가 그림에 박혀 있음)

## 요구사항 (사용자, 2026-11-04)
1. 배너 영상을 **AI 생성 영상**으로 바꾼다. 지금 것과 똑같을 필요 없음.
2. 지금보다 **화질이 좋아야** 한다.
3. 영상 안의 **글자(로고·문구·메뉴 4개)를 없앤다.**

## 조사로 확인한 사실
- 화질이 나쁜 원인은 두 가지: 원본이 **GIF(256색, 10fps)** 라 분홍 배경에 띠(밴딩)가 생기고 움직임이 끊김. 해상도(1920폭)는 문제 아님.
- 글자는 모델 몸 위에 겹쳐 있어 기존 영상에서 지우는 방식(인페인팅)은 품질이 안 나옴 → **새로 생성**이 맞다.
- 이 작업 환경에는 **영상·이미지 생성 도구가 없다.** 생성은 외부 서비스(Kling·Runway·Veo·Hailuo 등)에서 사용자가 하고, 결과 파일을 받아 변환·적용한다. 로컬 ffmpeg 9 로 변환·크롭·루프·압축은 가능.
- 생성 서비스는 대부분 **16:9(1920×1080) 5~10초**로 뽑아 준다. 배너는 2.9:1(1920×660)이라 위아래 각 210px 을 잘라야 함 → 피사체를 가운데 띠에 두도록 프롬프트에 명시.
- 글자가 없어지면 `index.html` 의 투명 링크 4개(글자 위에 얹은 `<nav aria-label="배너 메뉴">`)는 근거가 사라진다 → 같이 제거.
- 사이트에는 `assets/logo.png`(흰 배경용) 와 Pretendard 글꼴이 있어, 원하면 글자를 **HTML 로 다시 얹는** 것도 가능(선택 사항, 아래 결정 3).

## 설계 결정 (코드 쓰기 전 합의)
1. **생성 방식**: 이미지→영상(image-to-video) 권장. 먼저 글자 없는 정지 이미지 1장을 만들고(현재 포스터를 스타일 참고로 첨부), 그것을 영상으로 움직인다. 텍스트→영상 직행보다 얼굴·색감이 안정적이다. 서비스 추천 순: Kling 2.x(1080p, 10초, 루프 옵션) → Runway Gen-4 → Google Veo. 어느 것이든 **1080p·24fps 이상·5~10초·무음·워터마크 없음(유료 플랜)** 조건.
2. **규격**: 받은 영상(1920×1080)을 ffmpeg 로 가운데 띠 1920×660 크롭 → **24fps 유지** → MP4(H.264 CRF 20) + WebM(VP9 CRF 30). 용량 상한을 올린다: MP4 ≤ 3MB, WebM ≤ 2.5MB(현재 0.29/0.17MB). 포스터는 첫 프레임 JPG ≤ 200KB. 끊김 없는 반복이 필요하면 정→역 재생을 이어 붙여(ping-pong) 루프를 만든다.
3. **글자 처리**: 영상에는 글자 0개. HTML 로 다시 얹을지는 **선택**:
   - (A) 아무것도 안 얹음 — 가장 단순. 투명 링크 4개 제거. **기본값.**
   - (B) 로고 PNG + 문구 2줄 + 메뉴 4개를 HTML 텍스트로 왼쪽 가운데에 얹음 — 진짜 링크·검색엔진 노출·수정 쉬움. 모바일에서는 숨김. 원하면 작업 7 로 추가.
4. **마크업 변경 최소화**: `<section id="hero-banner">` 안만 바꾼다. 비율 `1920/660`, 모바일 240px 가운데 자르기, 포스터 preload, reduced-motion 처리는 그대로.
5. **원본 보관**: 생성 서비스에서 받은 원본(1080p)은 프로젝트 루트 `banner-src/` 에 두고 사이트 폴더에는 넣지 않는다(기존 GIF 와 같은 규칙).

## 위험 요소
- **생성 품질 편차**: AI 영상은 손가락·치아·머리카락 경계가 뭉개질 수 있다. 후보를 2~3개 받아 4번에서 고른다. 손이 얼굴에 닿는 포즈는 변형이 잦으니 프롬프트에서 손을 어깨 아래로 두거나 손 없는 구도를 권한다.
- **초상권·약관**: 생성 서비스의 상업 이용 허용 여부(유료 플랜) 확인. 실존 인물 닮은꼴 생성 금지.
- **의료광고 규제**: 배너에 글자가 없어도 시술 전후를 암시하는 연출(피부 변화 비교 등)은 피한다. 모델 컷은 분위기 연출만.
- **용량 증가**: 24fps·6초면 MP4 1.5~3MB. 모바일 LCP 에 영향 가능 → 6번에서 모바일용 소형 소스로 대응. 포스터가 먼저 보이므로 체감 지연은 작다.
- **루프 이음새**: 생성 영상 처음·끝이 달라 반복 시 튄다. ping-pong 루프로 해결되지만 길이가 2배가 되므로 원본은 4~5초가 적당.
- **색 재현**: 배경색을 현재 포스터(#E9C9C6)와 맞추려면 생성 시 색 지정이 완전히 먹지 않는다. ffmpeg 색 보정보다는 `section` 배경색(`bg-[#e9c9c6]`)을 새 영상 배경색에 맞춰 바꾸는 쪽이 쉽다.
