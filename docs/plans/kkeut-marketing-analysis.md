## 설계 결정 (코드 쓰기 전 합의)
- **매출 기준**: 주지표는 **회계 인식 순매출**(회원권 사용분 포함·충전 제외 = 시술이 소비된 시점). 세무 기준 **순 수납**은 참고 열로 병기. 둘의 차이(회원권 충전−사용)는 "회원권" 블록에서 설명.
- **채널 귀속 규칙**(가정은 노란 입력 셀로 두고 월마다 조정):
  - 여신티켓: 정산서 결제금액 합(없으면 화면 판매액 × 정산율 가정) → 직접 귀속.
  - 네이버 예약·스마트콜: 예약 474건 × 내원율(가정) × 객단가(매출 파일 실측 = 순매출 ÷ 고유 환자) → 추정 귀속.
  - 검색광고: 클릭 → 플레이스 유입의 일부로 보고 별도 귀속하지 않음(비용만). "내원 경로" 데이터가 오면 실측으로 교체.
- **비용**: 매체비(검색광고 3,228,955 + 여신티켓 광고비 + 기타) 와 운영비(400만) 를 분리해 ROAS 를 두 가지(매체비 기준 / 총비용 기준)로 낸다.
- **구조**: 입력 시트(원자료·가정)와 계산 시트(수식)를 분리. 월별은 **열**로 늘린다(10월 → 11월 …). 수식은 SUMIFS·INDEX/MATCH 만 사용(LibreOffice 없음 → Excel 이 열 때 계산, 손검산 목록으로 검증).
- **파일 구조**: 원자료 `data/kkeut/<YYYY-MM>/raw/`, 정규화 CSV `data/kkeut/<YYYY-MM>/`, 스크립트 `scripts/kkeut/`, 결과 xlsx 는 프로젝트 루트(+ OneDrive 끗한의원 폴더 사본).
- 환자 개인정보(이름·ID)는 결과 xlsx 에 넣지 않는다. 집계만 싣고 원자료는 `data/` 에 둔다(`.gitignore` 대상).

- **회원권 이중 계산**: 충전(수납)과 사용(매출)을 같이 더하면 과대. 2번 검산식(총 매출 − 사용 + 충전 = 총 수납)을 시트에 수식으로 둔다.
